# Requisitos Não Funcionais (RNF)

*   **RNF01 - Tecnologias Frontend:** O desenvolvimento da interface gráfica e do painel deve ser feito obrigatoriamente utilizando a biblioteca React[cite: 1]. O código deve estar contido na pasta `frontend/` e utilizar conceitos de componentes, estado e renderização[cite: 1].
*   **RNF02 - Tecnologias Backend:** O backend do sistema deve ser construído utilizando Node.js (com Express), Java (com Spring Boot) ou Python (com Flask/FastAPI)[cite: 1]. A escolha deve ser tecnicamente justificada no README do projeto[cite: 1].
*   **RNF03 - Persistência de Dados:** O sistema deve utilizar o banco de dados MySQL 8.0 para garantir o armazenamento das informações, senhas e auditorias[cite: 1].
*   **RNF04 - Tratamento de Concorrência:** O backend e o banco de dados devem garantir a integridade da fila[cite: 1]. O sistema deve tratar a concorrência no momento em que dois ou mais atendentes solicitarem a próxima senha simultaneamente, impedindo que a mesma senha vá para guichês diferentes[cite: 1].
*   **RNF05 - Disponibilidade e Resiliência:** O frontend e o painel de senhas devem possuir um comportamento adequado (tratamento de erros) diante de possíveis quedas ou falhas do backend e banco de dados[cite: 1].
*   **RNF06 - Regra de Negócio de Prioridade (Desempenho/Algoritmo):** A distribuição das senhas na fila pelo sistema (Agente Sistema) deve calcular a chamada utilizando estritamente a proporção matemática e lógica de: `[SP] -> [SE ou SG] -> [SP] -> [SE ou SG]`[cite: 1]. A prioridade máxima é sempre da SP, com prioridade mínima para SG, e a SE sendo atendida preferencialmente após uma SP[cite: 1].
*   **RNF07 - LGPD e Privacidade:** O totem interativo deve permitir acesso livre e não logado ao Agente Cliente, garantindo que o cliente interaja anonimamente e nenhum dado pessoal desnecessário seja coletado durante a emissão da senha[cite: 1].
